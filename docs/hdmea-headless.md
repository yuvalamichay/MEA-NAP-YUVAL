# Headless MATLAB analysis of converted hdMEA recordings

`MEApipeline_headless_retinal` runs Steps 2–4 using the current MATLAB
pipeline. It accepts existing SpyKING CIRCUS spikes and custom electrode
coordinates without launching the GUI. The branch's current burst analysis
is used, including `bakkumNetworkBurstMergeGapMs` (20 ms by default).

## Run existing converted data

Required inputs are:

- `<recording>_spikes.mat` files containing `spikeTimes`, `channels`, and
  `spikeDetectionResult.params.fs`/`.duration` (or `.Params` metadata).
- A batch CSV with recording name (without `_spikes.mat`), age, and group.
- A custom-layout CSV containing unique numeric `channel` identifiers and
  `x_norm`, `y_norm` coordinates between zero and one. Preserve relative x/y
  scale when normalizing. The converter writes this CSV.

In MATLAB, open the repository folder and run:

```matlab
addpath('examples');
config = hdmea_config_example('/absolute/path/to/Retinal MEA analysis');
MEApipeline_headless_retinal(config);
```

The example expects `MEANAP_spikes/MEANAP_batch.csv` and
`MEANAP_spikes/meanap_custom_coords.csv` inside that data folder. Set
`config.outputDataFolder` to choose where to save results. A timestamped run
name is generated by default. The runner creates channel-only placeholders
under that run's `ChannelPlaceholders` folder when `config.rawData` is omitted.
An explicit `rawData` path can instead point to existing channel placeholders.

A minimal configuration can also be constructed directly:

```matlab
config.spikeDetectedData = '/absolute/path/to/MEANAP_spikes';
config.spreadSheetFileName = '/absolute/path/to/batch.csv';
config.customCoordCsv = '/absolute/path/to/meanap_custom_coords.csv';
config.outputDataFolder = '/absolute/path/to/results';
config.outputDataFolderName = 'RetinalRun';
config.FuncConLagval = [10 25 50];
config.cartographyLagVal = config.FuncConLagval;
MEApipeline_headless_retinal(config);
```

For terminal execution, save `config` in a MAT file:

```matlab
save('/absolute/path/to/retinal_config.mat', 'config');
```

Then run from the repository folder:

```bash
matlab -batch "MEApipeline_headless_retinal('/absolute/path/to/retinal_config.mat')"
```

MAT files containing a saved `Params` struct are accepted too. The entry
point always starts a fresh analysis at Step 2, with spike detection,
stimulation analysis, Suite2p mode, and GUI mode disabled. Other parameter
overrides are retained after `AdvancedSettings` supplies missing defaults.
The current pipeline also accepts an explicit Params struct with
`Params.guiMode = 0`; existing GUI entry points retain their default behavior.

The retinal defaults are one **25 ms** lag, 200 thresholding repeats, tail
0.05, and PNG output. `config.csvRange = [2 3]` selects two recording rows
from the batch CSV (row numbers include the header). The default is all
recordings. Analysis choices should be recorded with the results rather than
inferred from an hdMEA hardware type.

## Several recordings with different layouts

Either set `config.customCoordCsv` to a cell array of absolute CSV paths, one
for each selected batch row, or add a `CustomCoords` column to the batch CSV.
Paths in that column may be relative to the batch CSV. `ChannelLayout` can
select `Custom` or a built-in layout for each recording. Coordinates are
matched to each recording's actual channel order, with an error for missing
channel identifiers.

Marker diameters are estimated from the nearest noncoincident node spacing
and capped at the previous plotting size. `config.nodeScaleFactor` overrides
that diameter in plotting coordinate units. Sorted units at the same
electrode still share a physical position; automatic sizing does not separate
them into artificial locations.

## Prepare new SpyKING CIRCUS / MaxWell data

The converter and validator are included at repository root:

```matlab
converted = spykingcircus_to_meanap_v3('/absolute/path/to/recording', ...
    'NodeMode', 'unit', 'AnalysisFs', 1000, 'AgeGroup', 6, 'Group', 'SOHU');
assert(verify_meanap_spikefile(converted.saveName));
```

The converter retains its original retinal metadata defaults (`AgeGroup = 6`,
`Group = 'SOHU'`); supply these options for other datasets. Group names must
be valid MATLAB field names. Use a separate input/output folder per recording
when converting several layouts; each conversion writes a layout CSV and a
single-recording batch CSV. Combine batch rows for a multi-recording run.

`AnalysisFs` defaults to 1,000 Hz to limit spike-matrix memory. Original
sample indices are converted to seconds using the acquisition rate, retaining
the original spike-time precision. The matrix bin width and the surrogate
circular-shift grid depend on `AnalysisFs`, so thresholded connectivity need
not be identical at another analysis rate. The converter records both rates.

By default, duration is floored to whole seconds and spikes outside the
retained interval are dropped. Coordinate normalization uses one scale for
x and y, and `FlipY` defaults to true. Optional TTL events are exported as
metadata; this headless runner does not enable stimulus analysis.

## Reliability changes

- Step 4 reuses the supplied external spike folder with `priorAnalysis = 0`.
- Missing `Ground` columns produce one empty grounding entry per recording.
- Experiment compilation first uses the exact current run filename. A single
  legacy match is accepted; ambiguous matches raise an error.
- Failure to assemble a combined side-by-side network figure prints a warning
  and continues, while individual figures and metric calculations remain
  available. The runner uses the painters renderer and restores the caller's
  path, folder, and figure defaults on exit.

## Regression checks

From the repository root:

```matlab
results = runtests('tests/matlab/testHdmeaHeadless.m');
assertSuccess(results);
```

The focused checks cover built-in/custom layouts, channel ordering,
per-recording coordinate files, dense/coincident marker spacing, exact result
selection, placeholder consistency, and conversion metadata/spike precision.
A full recording run remains necessary to validate the analysis and graphics
with the installed MATLAB/toolbox versions and the intended dataset.
